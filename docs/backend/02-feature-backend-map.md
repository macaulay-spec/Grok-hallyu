# 02 — Feature → backend requirements map (section 4)

Format per feature: **FEATURE → frontend behavior → DB → API → authorization → storage → realtime → notifications → scaling concern**. Table/RPC names refer to `schema.sql` and `08-api-spec.md`.

| FEATURE | Frontend behavior (exists) | DB | API | Authz | Storage | Realtime | Notifications | Scaling concern |
|---|---|---|---|---|---|---|---|---|
| **Accounts & sessions** | email/pw, Google PKCE, verify, reset, guest, demo | `auth.users` (Supabase), `profiles` (1:1, created by trigger), `handles` reserved list | Supabase Auth endpoints; `rpc claim_handle` | user = owner of `profiles.id = auth.uid()`; guest = no JWT (anon role) | — | — | verification/reset emails via custom SMTP | MAU quota (50K free / 100K Pro); email quotas (Resend 100/day free) |
| **Profile** | edit avatar/name/handle/bio/genres/favourite dramas; public profile page; counts | `profiles` (+ `follower_count`, `following_count` maintained by trigger) | `select profiles`, `update profiles` (RLS), `rpc profile_page(handle)` | update own row only; handle unique, 3–20 chars, not reserved | avatar → R2 `avatars/{uid}/{ulid}.jpg` (≤512 px, ≤200 KB) | — | — | avatar URLs hot in every card → cached at CDN; profile reads join‑free |
| **Follow users / dramas / actors / collections** | toggle, connections lists, fandom counts | `follows(follower_id, target_type, target_id)`; counters on `profiles`, `catalog_dramas`, `catalog_actors`, `collections` | `rpc set_follow(type,id,on)`; lists via `select follows` with joins | own rows; cannot follow blocked/blocking user | — | — | `follow` notification (user targets only) | fan‑out on read (feed queries join follows); counters denormalised |
| **Watchlist / progress / note / Up Next** | status, season/episode, note, up‑next rail, schedule | `watchlist_items(user_id, drama_id)`; `catalog_episodes(air_at)` | `rpc upsert_watchlist`, `select watchlist_items` | own rows; note private (never returned to others) | — | — | `episode_aired` when followed/watching drama airs and notify on | episode scheduler scans `catalog_episodes` hourly — index on `air_at` |
| **Posts (6 types)** | composer with limits, spoiler level, context, hashtags, mentions, images ≤6 / video ≤140 s, 15‑min edit, delete | `posts`, `post_media`, `post_actors`, `hashtags` via GIN on `text[]`, counters | `rpc create_post`, `rpc edit_post`, `update posts (soft delete)`, `rpc feed_*`, `rpc post_page(id)` | author only for edit/delete; edit window enforced in SQL; blocked users' posts filtered in RPCs | media keys must exist in `media_uploads` (status=ready, owner=author) before `create_post` succeeds | — | `mention` to mentioned users; `comment`/`reaction` to author | write amplification of counters; feed candidate window; hot post read caching (client 60 s) |
| **Media upload (images/video)** | picker, compression (to add), carousel, inline autoplay | `media_uploads(key, owner, kind, bytes, width, height, duration, status)` | Worker `POST /upload/presign`, `POST /upload/complete`; multipart for >20 MB | Worker verifies Supabase JWT; key prefix bound to `uid`; quotas per user/day | R2 bucket `hallyu-media` (public read via Worker/custom domain only) | — | — | R2 Class A ops (1M free) — one PUT per part; Class B for reads (10M free); 10 GB free storage → first paid line |
| **Comments (one level)** | reply, replyTo user, spoiler, reactions, delete | `comments(parent_id, reply_to_user_id)`; `posts.comment_count` | `rpc create_comment`, `select comments` (cursor), soft delete | author delete; post author may delete comments on own post (moderation right); blocked filtered | — | — | `comment` to post author, `reply` to parent author | pagination per post; index `(post_id, created_at)` |
| **Reactions (6 kinds)** | one kind per user per target, switch or remove, counts, "who reacted" | `reactions(user_id, target_type, target_id, kind)` unique; counter JSONB/6 int columns on target | `rpc set_reaction(type,id,kind|null)` | own rows | — | live episode room meter reads `episode_reaction_counts` | `reaction` to author (collapsed per hour) | hottest write path (8/MAU/month); trigger updates single row; no fan‑out |
| **Saves / Saved screen** | toggle, list | `saves(user_id, post_id)`; `posts.save_count` | `rpc set_save`, `select saves` | own rows | — | — | `collection_saved`‑like not needed (saves are private) | — |
| **Collections** | CRUD, add drama, cover, public/private, follow, share link | `collections`, `collection_items`, follows(target=collection) | `upsert collections`, `rpc set_collection_item`, `rpc collection_page(id)` | owner writes; private → owner only; public → anyone | cover = TMDB poster (no storage) | — | `collection_saved` (someone followed your collection) | none significant |
| **Drama / actor / episode pages** | tabs (discussion/review/…), fandom counts, cast, related, posts per episode, reaction meter | `catalog_dramas`, `catalog_actors`, `catalog_episodes`, `catalog_cast` mirror; `posts` by context; `episode_reaction_counts` | Edge `ensure-catalog` (server TMDB fetch → upsert); `rpc drama_page`, `rpc drama_posts`, `rpc episode_room` | catalog read public; catalog write only service role (function) | posters from TMDB CDN (no storage, attribution kept) | episode room: Broadcast channel `room:{drama}:{s}:{e}` while open | `episode_live` when a followed drama airs (opt‑in) | catalog mirror only for referenced dramas (not all of TMDB); refresh via pg_cron for airing shows |
| **Live episode room / reaction meter** | `LiveReactions` ambient meter, pill "N in the room" | `episode_reaction_counts(drama_id, season, ep, kind, count)` + `reactions` | `rpc episode_room` (initial), Realtime Broadcast for deltas, Presence for count | authenticated to broadcast; anon may read counts | — | **Supabase Realtime** only while a room is open; fallback polling 20 s | — | 200 peak conns free → rooms capped by tier; degrade to polling above cap |
| **Home rails (Up Next, Airing, Trending discussions, Live now)** | rails on Home | views: `v_airing_today`, `mv_trending_posts`, `mv_trending_dramas` | `rpc home_rails()` | public | — | — | — | materialised views refreshed every 5 min by pg_cron; single RPC = one round‑trip |
| **For You / Following / Shorts feeds** | infinite scroll, ranking, spoiler veil, seen‑memory (local) | `posts` + follows + watchlist + blocks/mutes | `rpc feed_for_you(cursor, limit)`, `rpc feed_following`, `rpc feed_shorts` | anon gets non‑personalised For You; personalised needs JWT | media URLs from `post_media.key` | — | — | candidate window (7 days) + scoring in SQL; keyset pagination; N+1 avoided by JSON aggregation; heaviest read path |
| **Search** | posts, people (local), dramas/actors (TMDB) | `posts.fts tsvector` (GIN), `profiles.fts`, `pg_trgm` on handle/display_name | `rpc search_posts(q, cursor)`, `rpc search_people(q)` | public (blocked filtered when authed) | — | — | — | GIN size; move to Meilisearch at millions of posts |
| **Notifications / Activity** | grouped list, unread badge, mark read, prefs + quiet hours | `notifications(user_id, kind, group_key, actor_ids[], post_id, drama_id, read_at)`, `push_tokens`, `push_outbox` (pgmq) | `select notifications`, `rpc mark_notifications_read`, `rpc register_push_token` | own rows | — | optional `postgres_changes` on own notifications (cheap, opt‑in) | Expo Push via `push-dispatch` Edge Function every minute; respects prefs/quiet hours | retention 90 days (pg_cron delete); fan‑out for `episode_aired` can be thousands → batched inserts + Expo batches of 100 |
| **Episode reminders** | local scheduled notifications today | `drama_notify(user_id, drama_id)` + `catalog_episodes.air_at` | `rpc set_drama_notify` | own rows | — | — | server push replaces local (local kept as offline fallback) | hourly scheduler; idempotency key per (user, episode) |
| **Report / block / mute / muted words** | report sheet (kinds post/comment/user/drama/collection, reasons, detail ≤500), block list, mute user/drama, muted words | `reports`, `blocks`, `mutes`; muted words in `profiles.prefs` | `insert reports` (rate‑limited RPC), `rpc set_block`, `rpc set_mute` | own rows; reports readable by moderators only | — | — | to moderators (email digest optional) | abuse: report spam limited 20/day/user; blocks filter in all feed RPCs |
| **Moderation** | none (user‑side only) | `moderation_actions`, `posts.state` ∈ active/hidden/removed, `profiles.state`, roles via `app_metadata.role` | Edge `moderate` (webhook on insert → OpenAI omni‑moderation → auto‑hide if score high); moderator RPCs `mod_set_state` | role = moderator/admin | — | — | `system` notification to the affected user | queue volume ≈ 0.02 reports/MAU/month |
